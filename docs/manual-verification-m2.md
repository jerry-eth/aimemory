# M2 人工验证清单

自动化已覆盖:解决方案构建(0 错误)、全部 98 个测试(含 2 个真实 DeepSeek 端点集成测试,密钥仅经环境变量传入)、启动 10 秒无崩溃冒烟、仓库无密钥泄漏检查。
以下项涉及真实桌面交互 / 真实大模型服务 / 通知与视觉效果,无法无头验证,请人工走查。

## 1. 大模型页 — DeepSeek 档案(BYOK)
- [ ] 打开「大模型」设置页 → 新增档案:名称 DeepSeek、Base URL `https://api.deepseek.com/v1`、粘贴自己的 API Key、保存
- [ ] 点「测试连接」→ 显示连接成功(失败时给出可读错误信息,不崩溃)
- [ ] 点「拉取模型」→ 下拉框列出真实模型列表,选择模型并保存
- [ ] 点「设为当前」→ 该档案标记为当前使用,重启应用后仍为当前

## 2. 大模型页 — Ollama 档案(本地,无密钥)
- [ ] 新增档案:Base URL `http://localhost:11434/v1`、模型名任意(如 `qwen2.5:7b`)、密钥留空 → **可正常保存**(本地地址不再要求密钥)
- [ ] 同样的空密钥 + 远程地址(如 `https://api.deepseek.com/v1`)→ 保存被拦,提示"远程服务必须填写 API 密钥"
- [ ] 本地 Ollama 运行时:测试连接成功、拉取模型能列出本地模型
- [ ] Ollama 未运行时:测试连接给出明确失败提示,不崩溃

## 3. 智能分析页 — 分析与缓存
- [ ] 打开「智能分析」页 → 点「开始分析」→ 等待后出现建议卡片(进程名、动作、理由、风险)
- [ ] 在进程/模板未变化的情况下再点一次「开始分析」→ 结果显示「(缓存结果)」,且 Token 统计不新增消耗
- [ ] 出现建议后点「强制刷新」→ 跳过缓存重新请求,Token 统计新增一条消耗
- [ ] 改变系统进程状态(新开大程序)后再分析 → 触发真实请求而非缓存
- [ ] 修改「自定义附加指令」或切换语言后再分析 → 缓存失效,触发真实请求

## 4. 压缩建议执行
- [ ] 建议卡片中对可压缩进程点「执行压缩」→ 完成提示 → 回仪表盘确认内存占用下降

## 5. 提示词模板
- [ ] 提示词设置中编辑默认模板(如要求理由用英文、或改变语气)→ 重新分析 → 建议理由的语言/风格随之变化
- [ ] 模板中的 `{memory_info}` `{process_list}` `{custom_instructions}` `{language}` 四个变量在发送前被替换为实际内容(可通过自定义模板写一句可识别的话验证)
- [ ] 点「恢复出厂」→ 模板内容回到内置默认,分析结果恢复原有风格

## 6. 自动触发
- [ ] 开启阈值触发,把阈值调到容易达到的值 → 让内存占用跑高(开多个浏览器标签)→ 收到自动分析完成的通知
- [ ] 当日重复触发达到每日上限后 → 不再自动分析,并有相应提示/状态说明(验证后把阈值改回正常值)

## 7. Token 统计
- [ ] 「Token 统计」页数字与数据目录下 jsonl 记录逐条一致(输入/输出 token 数)
- [ ] 在档案中填单价 → 统计页显示估算费用
- [ ] 把月度预算写一个很小的 Token 数(如 100)→ 触发自动分析时被预算闸门拦停,统计页/通知有体现
- [ ] 预算用满后在「智能分析」页手动点「开始分析」→ 被拦,状态栏提示已达月度预算

## 8. 内存泄漏告警
- [ ] 用测试程序或浏览器狂开标签制造持续增长 → 观察窗口(默认 30 分钟)内收到泄漏告警通知
- [ ] 泄漏告警行右侧点「智能分析」→ 以泄漏触发器发起分析,结果正常展示,Token 统计中该条触发方式为「泄漏」
- [ ] 「大模型」页「泄漏检测」卡片:开关、增长阈值(50-10000 MB)、观察窗口(5-120 分钟)改动即保存,重启后保持

## 9. 密钥存储检查
- [ ] 用文本编辑器打开数据目录下 `llm-profiles.json` → API Key 字段为 DPAPI 密文,**无明文密钥**
- [ ] 在别的用户账户/机器上拷贝该文件 → 无法解密出原密钥(可选)
