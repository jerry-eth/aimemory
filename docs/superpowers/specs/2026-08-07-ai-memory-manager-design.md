# AI 内存管家 — 产品需求文档(PRD)

- **版本**:v1.0
- **日期**:2026-08-07
- **状态**:待评审
- **技术栈**:WPF(.NET 8)+ MSIX,目标上架 Microsoft Store

---

## 1. 背景与目标

### 1.1 背景

Windows 内存清理工具品类成熟(Mem Reduct、WinMemoryCleaner、Wise Memory Optimizer 等),但存在三个空白:

1. **无智能决策**:现有工具的"自动化"止步于阈值规则,回答不了"该清哪个进程"。
2. **不敢碰进程级清理**:主流开源工具只做无损清理,无进程管理能力。
3. **商店渠道空白**:因 `runFullTrust` 受限能力门槛,主流工具均未上架 Microsoft Store。

### 1.2 产品定位

**第一个用大模型告诉你"内存去哪了"的内存管理工具。** 规则清理保底,大模型决策增值,白名单兜底安全。

### 1.3 目标用户

| 用户层 | 特征 | 核心诉求 |
|---|---|---|
| 普通用户 | 内存焦虑,不懂进程 | 一键清理、自动清理、不弄坏电脑 |
| 进阶用户 | 有自己的 LLM API Key(DeepSeek/OpenAI 等) | 智能分析、自定义提示词、Token 成本可控 |
| 极客用户 | 本机跑 Ollama | 完全离线、零 API 成本、可定制规则 |

### 1.4 成功指标(上架后 6 个月)

- 商店评分 ≥ 4.2
- 大模型功能开通率 ≥ 20%(说明差异化成立)
- 因误杀进程导致的差评/投诉 = 0

## 2. 技术架构

```
┌─────────────────────────────────────────────────────┐
│  WPF UI 层(中文/英文切换,托盘常驻)                  │
├─────────────────────────────────────────────────────┤
│  核心服务层                                          │
│  ├─ MemoryMonitor    内存采集(性能计数器 + 进程快照) │
│  ├─ RuleEngine       规则引擎(阈值/定时/间隔)        │
│  ├─ LLMService       大模型网关 + 提示词模板管理      │
│  │                   + Token 用量统计                │
│  ├─ CleanService     清理执行器(L1/L2/L3 分级)      │
│  └─ WhitelistService 白名单(排除列表 + 防误杀名单)   │
├─────────────────────────────────────────────────────┤
│  本地存储:JSON 配置文件(无数据库,保证体积)          │
│  位置:%APPDATA%/<AppName>/                          │
└─────────────────────────────────────────────────────┘
```

**模块职责单一、接口清晰**:UI 只依赖服务接口;LLMService 不直接执行清理,只输出结构化建议,由 CleanService 校验白名单后执行。

## 3. 安全分级设计(核心)

| 级别 | 手段 | 风险 | 确认策略 | 权限 |
|---|---|---|---|---|
| **L1 温和清理** | `EmptyWorkingSet` 压缩进程工作集 | 无(不杀进程、不丢数据) | 全自动,无需确认 | 普通权限 |
| **L2 系统缓存清理** | 清理 Standby List / 修改页列表 / 合并页列表 | 低(系统级缓存回收) | 首次授权后自动 | 需管理员(`allowElevation`) |
| **L3 结束进程** | 终止高占用进程 | 高(可能丢未保存数据) | **默认必须用户确认**;用户可对信任进程开启"免确认" | 普通权限(杀他人进程需管理员) |

**硬性保护(不可绕过)**:
- 内置系统关键进程名单(`system`、`csrss.exe`、`explorer.exe` 等),永不进入 L3 候选,UI 中不展示为可选项
- 用户白名单中的进程,L3 永不自动执行
- 大模型的 L3 建议必须经过白名单过滤后才展示给用户

| 编号 | 需求 | 优先级 |

| FR-3.1 | 阈值规则:内存占用率超过 X%(40–95 可调)持续 N 秒,自动执行 L1(可叠加 L2) | P0 |

### FR-4 大模型集成

| 编号 | 需求 | 优先级 |
|---|---|---|
| FR-4.1 | 支持 OpenAI 兼容协议:用户配置 Base URL + API Key + 模型名(覆盖 OpenAI/DeepSeek/Kimi/通义/Azure 等) | P0 |
| FR-4.2 | 支持 Ollama 本地模型:配置地址(默认 `http://localhost:11434`)+ 模型名 | P0 |
| FR-4.3 | 配置保存后提供"测试连接"按钮,验证 Key 有效性并列出可用模型 | P0 |
| FR-4.4 | 多配置档案:可保存多套配置,一键切换 | P1 |
| FR-4.5 | API Key 使用 Windows DPAPI 加密存储,严禁明文落盘 | P0 |

**分析流程**:采集进程快照(名称/内存/路径/签名/运行时长)→ 注入提示词模板 → 调用 LLM → **强制 JSON Schema 输出**(建议清单:进程名、建议动作 L1/L3、理由、风险等级)→ 白名单过滤 → 展示建议卡片 → 用户一键执行或忽略。

**触发方式(三种,均可开关)**:
- FR-4.6 手动触发:主界面"智能分析"按钮
- FR-4.7 阈值触发:内存超阈值时自动分析;**每日调用次数上限可配(默认 10 次)**,防刷费
- FR-4.8 定时触发:每 N 小时/每天固定时间生成分析报告
- FR-4.9 **结果缓存**:对进程快照做哈希,24 小时内相同快照直接复用上次结果,不重复调用,节省 Token(用户可手动强制刷新)

## 6. 隐私与合规

1. **数据最小化**:进程快照仅在大模型触发时发送给用户**自己配置**的 API 端点,软件不内置任何遥测/上报。
2. **隐私政策**:商店上架需挂隐私政策页,明确说明"数据只发往用户自选端点"。
3. **商店能力声明**:
   - `runFullTrust`(受限能力,需在 Partner Center 填写用途说明:内存管理需要进程级操作)
   - `allowElevation`(L2/L3 管理员操作)
   - StartupTask(开机自启)
4. **商店政策风险点**:避免"夸大系统问题恐吓用户"类文案(政策 10.8.7);L3 默认需确认恰好满足"不得未经用户同意修改系统"的要求。

## 9. 待办风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| `runFullTrust` 审核被拒 | 无法上架 | 提交说明中详细描述内存管理用途;参考同类上架案例;必要时先做非商店渠道分发 |
| LLM 输出不稳定导致误杀 | 用户数据丢失 | JSON Schema 强约束 + 白名单硬过滤 + L3 默认需确认 + 未保存检测 + 后悔药 五重防护 |
| L2 提权每次弹 UAC | 自动清理半夜弹窗,严重劝退 | M1 必须完成方案设计:安装时一次性创建提权计划任务/辅助进程,后续静默调用 |
| C 盘迁移破坏应用 | 软件无法运行、差评 | Junction 链接无感迁移 + 占用检测 + 迁移日志回退 + 系统路径硬白名单 |
| 用户误以为"清理内存=提速" | 差评 | UI 文案教育(显示真实释放量,不夸大效果) |
