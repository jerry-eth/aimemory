# C 盘瘦身商业交付版需求文档

## Introduction

本需求用于将“C 盘瘦身”从当前“扫描 → 可选 LLM 建议 → 删除/迁移”的测试版，完善为可独立使用、可恢复、可审计、可在普通 Windows 10/11 设备安全交付的商业版本。

核心原则：

1. **LLM 非必需依赖**：没有 API Key 时，扫描、分类、清理、迁移记录和回退仍然可用；LLM 只作为可选增强。
2. **安全优先**：任何删除、迁移操作都必须经过本地硬保护、使用中检测、空间校验和用户确认；禁止依赖 LLM 或 UI 过滤来保证安全。
3. **可恢复、可审计**：删除优先进入回收站；迁移必须保留可验证的操作记录，并在异常中断或用户操作后提供回退能力。
4. **商业交付**：异常、权限不足、文件被占用、目标盘空间不足、路径失效等情况必须给出可理解的结果，不得静默成功或让页面卡死。

## Design Specification

### 1. Purpose Statement

C 盘瘦身页帮助普通 Windows 用户发现 C 盘中占用空间较大的、可安全处理的内容，并在不误删系统文件、不影响正在使用的软件的前提下完成清理或跨盘迁移。页面必须让用户清楚知道“发现了什么、风险是什么、将释放多少空间、失败或回退会发生什么”。

### 2. Aesthetic Direction

**Industrial / utilitarian（工业化工具台）**：以资源状态、风险等级和可执行动作作为视觉主线，减少装饰性动效，强调清晰的状态反馈和可审计操作。

### 3. Color Palette

- `#0F172A`：深色工具台背景和标题区
- `#1E293B`：卡片、表格和操作区域
- `#22C55E`：安全、可清理、已完成
- `#F59E0B`：需要确认、空间不足、使用中
- `#EF4444`：禁止操作、失败、危险路径
- `#E2E8F0`：主要文字和表格分隔线

禁止使用紫色、紫罗兰、靛蓝、洋红或蓝紫渐变作为主视觉。

### 4. Typography

使用 Windows 原生 **Segoe UI**，标题使用 SemiBold，正文使用 Regular，路径和错误详情使用等宽字体 `Cascadia Mono`（系统不可用时回退到 Segoe UI）。

### 5. Layout Strategy

使用“非对称工作台”布局：顶部为 C 盘空间状态和扫描控制的横向状态带，左侧为按风险分组的候选摘要，右侧为可筛选、可排序、支持多选的明细表；删除、迁移和历史记录作为下方独立操作区。危险操作不与扫描按钮混排，并在操作区持续显示目标数量和预计空间。

## Requirements

### Requirement 1 - C 盘空间概览

**User Story:** 作为用户，我希望在开始瘦身前看到 C 盘总空间、已用空间、可用空间和压力等级。

#### Acceptance Criteria

1. 当用户进入 C 盘瘦身页时，系统应显示 C 盘总容量、已用容量、可用容量、占用率和最近一次扫描时间。
2. 当 C 盘不可访问或未找到时，系统应显示明确错误和重新检测入口，不得让页面空白。
3. 当空间信息刷新时，系统应在后台执行，不阻塞页面交互；刷新失败不得清除上一次有效结果。
4. 当可用空间低于配置阈值时，系统应显示“高压力”状态并突出可安全处理项；当空间充足时，系统应提示不建议频繁清理。

### Requirement 2 - 安全候选发现与分类

**User Story:** 作为用户，我希望扫描能覆盖常见 C 盘占用来源，同时不会把系统关键路径列为可操作项。

#### Acceptance Criteria

1. 当用户点击扫描时，系统应异步扫描临时文件、浏览器缓存、回收站、用户缓存、Windows 可安全清理缓存和用户数据目录，并显示阶段、已处理项目数和可取消状态。
2. 当扫描遇到无权限、文件正在使用、路径消失、符号链接或 junction 时，系统应跳过该项并记录可理解的跳过原因，不得因单个项目失败而终止整次扫描。
3. 当扫描发现系统目录、Windows 安装目录、Program Files、用户配置关键目录、当前应用数据目录或包含 reparse point 的路径时，系统应将其标记为受保护或排除，不得进入默认删除/迁移候选。
4. 当同一路径通过多个来源发现时，系统应去重并保留最具体的分类和风险说明。
5. 当扫描完成时，系统应按大小降序展示候选，并提供分类、路径、大小、文件数、风险、最后访问/修改信息（可获取时）和建议动作。
6. 当用户取消扫描时，系统应在合理时间内停止后续枚举，保留已完成的部分结果并明确标注“扫描已取消”。

### Requirement 3 - 本地规则建议，LLM 可选

**User Story:** 作为不配置 API Key 的用户，我希望仍然能获得可执行的瘦身建议。

#### Acceptance Criteria

1. 当扫描完成且没有激活 LLM 档案时，系统应依据本地规则生成“可安全清理、建议确认、仅建议迁移、禁止操作”分类，不得要求用户配置 LLM 才能继续。
2. 当用户配置并主动开启 LLM 分析时，系统应将本地硬过滤后的摘要发送给 LLM，不得发送受保护路径、API Key、文件内容或完整隐私路径之外的无关数据。
3. 当 LLM 不可用、超时、返回非法 JSON 或达到预算时，系统应保留本地规则建议并显示降级原因，不得阻塞 C 盘瘦身的清理和迁移功能。
4. 当 LLM 建议与本地安全规则冲突时，系统应以本地安全规则为准，禁止危险建议进入可执行列表。

### Requirement 4 - 删除到回收站

**User Story:** 作为用户，我希望清理文件时可以恢复，而不是直接永久删除。

#### Acceptance Criteria

1. 当用户勾选可清理项并点击删除时，系统应显示路径、项目数、预计空间和“移入回收站而非永久删除”的确认对话框。
2. 当用户确认删除时，系统应在执行前再次检查路径保护、路径是否仍存在、是否为目录 junction/reparse point、是否属于当前运行关键程序，并逐项执行。
3. 当单项删除成功时，系统应从待处理列表移除并刷新 C 盘空间；删除结果必须包含成功、跳过和失败明细。
4. 当文件被占用、权限不足或路径已消失时，系统应跳过该项并说明原因，不得把整批误报为成功。
5. 当系统无法保证回收站操作而只能永久删除时，系统应拒绝操作并提示用户，不得自动降级为永久删除。
6. 当删除完成后，系统应保存操作记录，包含时间、路径、类别、估算大小、实际结果和错误信息（如有）。

### Requirement 5 - 跨盘迁移

**User Story:** 作为用户，我希望把大型用户数据安全迁移到其他盘，并可以在需要时回退。

#### Acceptance Criteria

1. 当用户选择迁移项时，系统应只允许用户数据和本地规则标记为可迁移的路径；系统目录、应用安装目录、运行中关键目录和不支持的文件系统路径必须拒绝。
2. 当用户选择目标盘时，系统应验证目标盘存在、可写、不是源盘、剩余空间大于源数据估算值并满足路径长度要求。
3. 当迁移开始前，系统应执行占用检测、目标空间复核、源路径复核和目标路径冲突检查；任一硬检查失败时应阻止该项执行并说明原因。
4. 当迁移执行时，系统应先复制文件并校验文件数量/大小，校验成功后才替换源路径；复制失败、校验失败或用户取消时不得删除源数据。
5. 当迁移需要创建 junction 或等效重定向时，系统应记录源路径、目标路径、重定向类型、创建时间和原始属性，并在创建失败时恢复源状态。
6. 当迁移完成后，原路径应保持可访问，应用通过原路径访问时应能正常工作；目标目录应保留必要的文件属性和目录结构。
7. 当用户回退迁移时，系统应先验证目标数据和源路径状态；回退失败不得删除唯一数据副本，并应显示需要用户处理的具体原因。
8. 当迁移过程中应用正在使用源目录时，系统应优先阻止迁移并列出占用进程，而不是强制关闭进程。
9. 当迁移记录损坏、目标盘被移除或应用重启后，系统应保留记录并将状态标记为“需人工检查”，不得假设迁移成功或自动删除数据。

### Requirement 6 - 操作进度、取消与响应

**User Story:** 作为用户，我希望长时间扫描、删除和迁移过程可见且不会让软件假死。

#### Acceptance Criteria

1. 当扫描、删除或迁移超过 1 秒时，系统应显示阶段、进度或已处理数量、当前路径和取消按钮。
2. 当用户点击取消时，系统应停止后续操作；已完成的安全操作保留，并显示部分完成结果。
3. 当后台任务执行时，主窗口、导航和历史查看仍应保持响应。
4. 当操作结束、取消或失败时，系统应恢复按钮状态，避免重复执行或永久显示忙碌状态。

### Requirement 7 - 审计、历史和诊断

**User Story:** 作为用户，我希望知道瘦身做过什么，出了问题可以定位。

#### Acceptance Criteria

1. 当任意删除或迁移操作结束时，系统应保存本次操作摘要和逐项结果。
2. 当用户查看历史时，系统应能按时间看到扫描、清理、迁移、回退和失败记录。
3. 当应用发生异常时，系统应提供不含 API Key、密码、私钥和文件内容的诊断信息；路径可按隐私设置进行脱敏。
4. 当历史文件损坏时，系统应备份损坏文件并恢复可写的新日志，不得阻止应用启动。

### Requirement 8 - 权限与商业交付

**User Story:** 作为普通用户，我希望安装后无需额外配置就能使用安全功能，同时需要管理员权限时能得到清晰提示。

#### Acceptance Criteria

1. 当用户以标准账户运行时，扫描和回收站删除应尽可能可用；需要管理员权限的操作应在执行前解释原因并通过 UAC 请求提权。
2. 当用户取消 UAC 时，系统应保持运行并显示操作取消，不得崩溃或退出。
3. 当用户首次安装、升级或卸载时，用户配置、白名单、迁移记录和密钥存储策略应符合产品说明，且升级不得静默删除历史数据。
4. 当生成商业安装包时，系统应提供 x64 自包含包、正式签名策略、安装/升级/卸载验证记录和不包含私钥/API Key 的交付物。

### Requirement 9 - 自动化和人工验收

**User Story:** 作为交付负责人，我希望每次发布前都能证明 C 盘瘦身核心路径没有回归。

#### Acceptance Criteria

1. 系统应为候选发现、路径保护、扫描取消、规则建议、回收站删除、空间校验、复制校验、junction 创建/回退、占用检测和异常恢复提供自动化测试。
2. 系统应提供仅使用临时目录和测试替身的测试模式，禁止自动化测试直接操作真实 Windows 系统目录或真实用户数据。
3. 发布前应完成 Release 构建、全量测试、安装、升级、卸载、标准用户、UAC 取消、目标盘移除和进程占用等人工验收。
4. 发布包不得包含 `.env`、API Key、Token、密码、`.pfx`、私钥或测试用户数据。

## Out of Scope

- 不自动永久删除用户文件。
- 不强制终止占用文件的第三方软件。
- 不自动迁移 Windows 系统目录、Program Files、完整 AppData 或未知应用数据库。
- 不承诺“清理后永久增加可用空间”；空间会随 Windows 和应用重新使用而变化。
- 不把 LLM 作为安全决策或执行权限来源。

## 当前实现需要重点核查的风险

1. 当前扫描结果主要依赖目录遍历，需补充可取消、进度、空间状态和本地规则建议。
2. 当前 C 盘瘦身页在没有 LLM 档案时不能继续分析，需要改为 LLM 可选。
3. 当前迁移路径涉及 robocopy、junction、删除源目录和回退，必须通过复制后校验、状态机和异常恢复重新验收。
4. 当前候选目录含用户目录一级目录，商业版需要收紧 AppData、应用目录和运行中目录的默认迁移范围。
5. 当前测试清单仍有干净设备安装、升级、标准用户和 UAC 取消等未完成项。
